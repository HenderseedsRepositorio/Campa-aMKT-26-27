Los términos que te van a aparecer cuando trabajamos juntos, explicados de productor a productor. Sin chamuyo técnico.

Los 6 términos que importan

Cada uno con su traducción al campo 🚜

🏠

Repositorio (repo)

= El galpón

La carpeta madre en la nube donde vive TODO el proyecto: los posteos, las plantillas, el calendario, la página web. Tu repo se llama Campa-aMKT-26-27.

📸

Commit

= El asiento en el cuaderno de campo

Una "foto" de los cambios, guardada con fecha, autor y una nota de qué se hizo. Queda el historial completo: siempre podés ver qué cambió y volver atrás.

🚚

Push

= Despachar el camión

Subir los commits a GitHub. Hasta el push, los cambios están solo en la computadora donde se trabajó. Después del push, ya están en la nube, a salvo y visibles.

🌱

Rama (branch)

= El lote de ensayo

Una copia paralela del proyecto para trabajar tranquilo sin tocar lo oficial. Se prueba ahí y, si funciona, recién después se pasa al "campo entero".

📋

Pull Request (PR)

= El remito antes de descargar

El pedido formal de pasar los cambios de una rama a otra. Te muestra TODO lo que va a cambiar, línea por línea, para que lo revises antes de aceptar.

✅

Merge

= Descargar el camión al galpón

Aceptar el Pull Request: los cambios entran a la rama principal y quedan oficiales. Si el remito no te cierra, no descargás: pedís correcciones o lo rechazás.

El flujo completo, paso a paso

Qué pasa desde que me escribís hasta que el contenido queda listo

💬

1. Vos pedís (desde el celular)

Abrís Claude Code y tirás el pedido.

"Generá los 3 posts de la semana que viene"
🤖

2. Claude trabaja en una rama

Leo las reglas del repo (CLAUDE.md, marca, contexto) y creo o edito los archivos en el lote de ensayo.

📸

3. Commit

Guardo la foto de los cambios con su descripción: "3 posts semana W25".

🚚

4. Push

Despacho el camión: los cambios suben a GitHub y ya quedan en la nube.

📋

5. Pull Request (opcional)

Si la rama no es la principal, revisás el remito y aceptás con Merge. En tu repo hoy este paso no existe: trabajo directo en la rama principal.

🎉

6. Listo y publicado

El contenido queda oficial en el repo. Y si el cambio tocó la carpeta docs/, un robot (GitHub Actions) republica la página web solo, sin que nadie haga nada.

GitHub ActionsEl robot

Un empleado que no duerme: mira los push, y cuando detecta cambios en la página, la republica. Esta misma infografía llegó a tu pantalla por ese circuito.

💡 La idea clave: nada se pierde y nada se pisa. Cada cambio queda registrado (commit), respaldado en la nube (push), y si algún día querés control de calidad antes de aprobar, se agrega el paso del remito (Pull Request + Merge). GitHub guarda el historial completo: siempre se puede volver atrás.
